# PhotoSift

整理相片、幫你挑出適合參加攝影比賽的作品。大量的初選工作交給在自己電腦上執行的模型，外部模型（Claude、GPT 或 Gemini）只在需要判斷力的地方出手，所以幾千張照片的相片庫只會用到幾萬個 token。

PhotoSift 只讀取你的照片。分類、評分和挑選都記錄在它自己的資料庫裡，不會搬動、修改或刪除任何原始檔。

## 它怎麼運作

每一層都比上一層貴，所以每一層只處理上一層篩剩的照片。

| 階段 | 誰做 | 做什麼 | 花費 |
|---|---|---|---|
| 匯入 | 程式 | 掃描資料夾，讀拍攝時間、GPS、相機資訊，做縮圖，量清晰度與曝光 | 無 |
| 影像分析 | 地端 SigLIP 2 | 找出連拍與重複並挑出每組最佳、依時間地點切成事件、分主題、文字搜尋、美感初評 | 無 |
| 標註 | 地端視覺語言模型（Ollama） | 每張寫一句描述、幾個標籤，給構圖、光線、意境等分數，替事件命名 | 無 |
| 評分標準 | 外部模型 | 依比賽主題寫評分標準，並改寫成地端小模型看得懂的評審須知 | 只送文字 |
| 地端評審 | 地端視覺語言模型 | 照評分標準把候選照片逐張評過 | 無 |
| 校準 | 外部模型 | 評一小批樣本，量出地端評審準不準，並告訴它哪裡看錯了 | 預設 16 張 |
| 決選 | 外部模型 | 只看排名最前面的入圍照片，逐張寫評語和後製建議，再並排比較排出名次 | 預設 24 張 |
| 後製 | 地端模型為主 | 提出調整方向、檢查自己修出來的結果；你用滑桿微調後匯出複本 | 無 |

外部模型和地端模型有兩種合作方式，兩種都用上了：

- **外部教地端**：外部模型寫評分標準；校準之後它會讀兩邊的分數，寫一份「修正提醒」給地端模型。按「依提醒重新評分」，地端模型帶著提醒重評一次，再和外部模型已有的分數比對，畫面上會顯示一致度有沒有提高。這一步不花 token。
- **地端先篩、外部決選**：只有通過地端初選的照片才會送給外部模型。

每次要把照片送到外部之前，畫面會先列出是哪幾張和預估的 token 數，按下確認才會送出。送出的是縮小後的複本，已經移除拍攝時間、相機與 GPS。

不設定外部模型也能用：評分標準改用內建的，初選完全在地端完成。

## 後製

在照片檢視畫面按 `E`（或點「後製」）進入修圖。只做整體調整、裁切和轉正，不會移除或添加畫面裡的任何東西，符合多數比賽「不可合成」的規定。

- **調整項目**：曝光、對比、亮部、暗部、色溫、色調、自然飽和度、飽和度、黑白、清晰度、銳利化、暗角、轉正、裁切（含常用比例）。
- **地端模型建議**：按「請地端模型建議」，模型會決定後製方向並直接套用。勾選「套用後自我複查」時，app 會把修圖前後的對照再給模型看，讓它修正過頭或不足的地方。不花 token。
- **外部評審的建議**：決選時，外部模型會順便為每張入圍照片提出調整建議，包在同一次呼叫裡，不需要另外上傳照片。在比賽名次列表按「後製」，再按「套用」即可。
- **外部模型複查**：對自己修的結果沒把握時，可以請外部模型看一眼。只上傳一張前後對照的縮圖，實測一次約 1,900 tokens。
- **匯出**：修圖只記錄成一組調整步驟，原始檔不會被更動，隨時可以重設。匯出時才以完整解析度產生一份 JPEG 複本，保留原本的拍攝資訊與色彩描述檔。比賽匯出時，修過圖的照片會多一份修圖後的版本。

按住空白鍵（或畫面下方的按鈕）可以看原圖。滑桿上按兩下會歸零。

模型擅長判斷方向（該提亮、該裁掉哪一邊），但給不出精準的數值，所以幅度是這樣決定的：模型給方向和強弱，app 量測照片實際偏離正常多少來決定要調多少。夜景、日落、表演現場這類本來就暗的照片不會因為量測而被提亮。轉正的角度也是量出來的，只有在建築或明確的地平線上才準，其他情況請自己用滑桿調。

## 安裝（macOS）

需要 Apple Silicon 的 Mac，以及已安裝的 [Ollama](https://ollama.com)。

1. 安裝 [uv](https://docs.astral.sh/uv/)（Python 的套件管理工具，會自動準備好 Python）：

   ```bash
   curl -LsSf https://astral.sh/uv/install.sh | sh
   ```

2. 取得程式並安裝相依套件（含 PyTorch，需要幾分鐘）：

   ```bash
   git clone https://github.com/kuanhuasu-source/PhotoSift.git
   ```

   ```bash
   cd PhotoSift && uv sync --no-dev
   ```

3. 下載地端模型。64 GB 記憶體建議這兩個（合計約 28 GB）：

   ```bash
   ollama pull gemma4:12b
   ```

   ```bash
   ollama pull gemma4:31b
   ```

   `gemma4:12b` 負責大量標註（速度優先），`gemma4:31b` 負責比賽初選（判斷力優先）。記憶體較小的電腦，設定頁會依記憶體大小建議其他模型。

4. 啟動：

   ```bash
   uv run photosift
   ```

   會開啟 PhotoSift 視窗。第一次分析照片時，會從 Hugging Face 下載影像分析模型（約 1.5 GB）。

5. 想要一個可以放進 Dock 的圖示：

   ```bash
   ./scripts/make_mac_app.sh
   ```

   會在專案資料夾產生 `PhotoSift.app`。它是一個啟動器，執行的就是這個資料夾裡的程式，所以建立之後不要搬動專案資料夾。

也可以用瀏覽器開啟，不開視窗：`uv run photosift --browser`。

## 開始使用

1. 到「設定」加入相片資料夾，按「開始分析」。幾千張照片大約需要幾分鐘到十幾分鐘，可以隨時取消，下次會接著做。
2. 在「設定」的地端模型選好標註模型和評審模型。
3. 回到「圖庫」按「地端模型標註」。它會從最有潛力的照片開始處理，不必一次跑完。
4. 要用外部模型的話，在「設定」選一家、貼上 API key、選好模型。
5. 到「比賽選片」新增比賽，填上主題和規則，照畫面上的四個步驟做。

在照片檢視畫面可以用鍵盤：`←` `→` 切換、`P` 挑選、`X` 淘汰、`0`–`5` 給星等、`E` 後製、`Esc` 關閉。

## 外部模型

| 提供者 | 預設模型 | 備註 |
|---|---|---|
| Claude | `claude-opus-5-5` | 透過官方 SDK。已啟用伺服器端的拒絕回退：若安全分類器拒絕某次請求，API 會自動改用它建議的模型重試。已用 `ant auth login` 登入的話可以不填 key |
| Gemini | `gemini-flash-latest` | |
| GPT | 無預設 | 模型名稱更新得很快，請儲存 key 之後按「列出可用模型」挑選 |

API key 存在 macOS 的鑰匙圈。也可以用環境變數 `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`、`GEMINI_API_KEY`。

「設定」最下方有每個模型的呼叫次數與 token 用量。填入你所用模型的單價，會一併顯示估計費用。

## 地端模型

預設連到 `http://localhost:11434` 的 Ollama。也可以在設定的「進階」改成 LM Studio 或其他 OpenAI 相容的本機服務。

比賽頁的校準步驟會顯示地端評審和外部評審的「排序一致度」。想比較兩個地端評審模型（例如 `gemma4:31b` 和 `qwen3-vl:32b`）哪個比較準，各跑一次看這個數字就知道。

## 資料放在哪裡

分析結果、縮圖和設定存在 `~/Library/Application Support/PhotoSift/`。刪掉這個資料夾就會回到全新狀態，你的照片不受影響。設定環境變數 `PHOTOSIFT_HOME` 可以改放別處。

支援 JPEG、HEIC、PNG、TIFF、WebP 與常見的 RAW 格式（CR2、CR3、NEF、ARW、RAF、RW2、ORF、DNG 等）。同名的 RAW 和 JPEG 視為同一張，匯出時會一起複製。

## 驗證狀況

這個版本是在 Linux 雲端環境開發的，以下是實際測過和還沒測過的部分。

已實測：

- 49 個自動化測試（`uv run pytest`），涵蓋匯入、品質判定、分組、事件切分、比賽流程、修圖引擎、後製建議、API，以及「原始檔不被更動」「金鑰不外洩」「上傳的複本不含拍攝資訊」等保證。
- 用真的 SigLIP 2 模型跑過影像分析與中文搜尋。
- 用 Gemini 跑過完整的比賽流程（評分標準、校準、決選與後製建議）和修圖複查。
- 用瀏覽器從介面操作過完整流程，包含修圖、套用建議與匯出，沒有錯誤。

還沒實測，第一次在 Mac 上執行時請留意：

- **真正的 Ollama**。開發環境無法安裝 Ollama，地端模型的部分（標註、評審、後製建議）是用一個替身服務測的：它實作同樣的 Ollama API，背後接的是雲端代管的 Gemma 4。
- **原生視窗與資料夾選擇器**（pywebview）和 `make_mac_app.sh`。這些只能在 macOS 上執行。若視窗開不起來，`uv run photosift --browser` 的功能完全相同。
- **Apple GPU（MPS）加速**、**HEIC 與 RAW 檔**的實際讀取與修圖。
- **iPhone 照片的色彩**。iPhone 照片使用 Display P3 色域，程式會把色彩描述檔一路帶到預覽和匯出檔，但手邊沒有真正的 P3 照片可以驗證顏色是否完全一致。
- **Claude 與 GPT**。開發環境沒有這兩家的金鑰，程式是依官方文件寫的，沒有對真實 API 呼叫過。
- 清晰度的判定門檻是用網路尺寸的範例照片調的，實際相機檔可能需要在設定裡調整「模糊判定門檻」。
- 後製建議的幅度是用少量範例照片調的。如果覺得模型普遍修得太多或太少，告訴我方向，可以再調。

## 開發

```bash
uv sync
```

```bash
uv run pytest
```

測試不需要下載模型，也不會連網。

`scripts/fetch_samples.py` 會從 Wikimedia Commons 下載一批自由授權的照片當示範相片庫，並產生 `CREDITS.json` 記錄每張的作者與授權。`scripts/dev_ollama_shim.py` 是上面提到的 Ollama 替身，僅供開發測試；使用它時照片會送到外部，不要拿來處理私人照片。

程式結構：

```
photosift/
  ingest.py      匯入：掃描、EXIF、縮圖
  quality.py     技術品質
  embedder.py    影像與文字的向量
  taxonomy.py    主題分類與美感初評
  grouping.py    連拍分組、事件、初步分數
  local_vlm.py   地端視覺語言模型
  cloud/         Claude、GPT、Gemini
  contest.py     比賽選片的四個步驟
  editing.py     修圖引擎：把一組調整套用到複本上
  retouch.py     後製建議：模型給方向、量測定幅度、複查修正
  server.py      本機 API
  web/           介面
```

介面使用 [Preact](https://preactjs.com)（MIT）與 [htm](https://github.com/developit/htm)（Apache-2.0），已包含在 `photosift/web/vendor/`。
