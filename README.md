# PhotoSift

整理相片、幫你挑出適合參加攝影比賽的作品。大量的初選工作交給在自己電腦上執行的模型，外部模型（Claude、GPT 或 Gemini）只在需要判斷力的地方出手，所以幾千張照片的相片庫只會用到幾萬個 token。

PhotoSift 只讀取你的照片。分類、評分和挑選都記錄在它自己的資料庫裡，不會搬動、修改或刪除任何原始檔。

## 它怎麼運作

每一層都比上一層貴，所以每一層只處理上一層篩剩的照片。相片庫越大，這個設計越划算：外部模型看的張數是固定的。

| 階段 | 誰做 | 做什麼 | 花費 |
|---|---|---|---|
| 匯入 | 程式 | 掃描資料夾，讀拍攝時間、GPS、相機資訊，做縮圖，量清晰度與曝光 | 無 |
| 影像分析 | 地端 SigLIP 2 | 找出連拍與重複並挑出每組最佳、依時間地點切成事件、分主題、文字搜尋、美感初評 | 無 |
| 光線時段 | 程式 | 由拍攝時間和 GPS 算出太陽高度，標出黃金時刻、藍調時刻、夜晚、白天 | 無 |
| 標註 | 地端視覺語言模型（Ollama） | 每張寫一句描述，並記錄主體、景別、光線、構圖手法、色調、氛圍、人數，給六項分數 | 無 |
| 你的偏好 | 程式 | 從你按過的「挑選」「淘汰」和星等學習，為全部照片打「像你會選的」分數 | 無 |
| 比賽規定 | 程式 | 拍攝期間、直橫式、解析度、器材、人物這些硬性規定，直接從拍攝資訊過濾 | 無 |
| 評分標準 | 外部模型 | 讀完你在問答精靈裡的回答，寫出評分標準、給地端模型的評審須知，以及十個左右「得獎照片可能呈現的畫面」 | 只送文字 |
| 候選召回 | 地端 SigLIP 2 | 用那些畫面描述比對全部照片，每一種詮釋都保留名額，再加上品質與你的偏好排出候選 | 無 |
| 地端評審 | 地端視覺語言模型 | 照評分標準把候選照片逐張評過 | 無 |
| 校準 | 外部模型 | 評一小批樣本並寫好評語，量出地端評審準不準，告訴它哪裡看錯了 | 預設 16 張 |
| 總表初選 | 外部模型 | 把候選拼成編號的縮圖總表（每 16 張一張圖），附上地端模型寫的文字說明，請它挑出要看原圖的 | 預設 48 張，3 張圖 |
| 決選 | 外部模型 | 只有被挑中的才送原圖，逐張寫評語和後製建議；校準時看過的不重送。最後用一張總表並排比較，排出名次 | 預設最多 12 張 |
| 後製 | 地端模型為主 | 提出調整方向、檢查自己修出來的結果；你用滑桿微調後匯出複本 | 無 |

外部模型和地端模型有三種合作方式：

- **外部教地端**：外部模型寫評分標準和找候選用的畫面描述。校準之後，它會讀兩邊的分數，寫一份「修正提醒」並留下高、中、低分的實例給地端模型參考。按「依提醒重新評分」，地端模型帶著這些重評一次，畫面上會顯示一致度有沒有提高。這一步不花 token。
- **地端先篩、外部決選**：外部模型先讀文字說明、看縮圖總表，只有它挑中的照片才會以原圖送出。
- **依一致度調整**：校準時兩邊看法差距越大，總表初選就看越多張（最多兩倍），把 token 花在地端評審不可靠的時候。

每次要把照片送到外部之前，畫面會先列出是哪幾張和預估的 token 數，按下確認才會送出。送出的是縮小後的複本，已經移除拍攝時間、相機與 GPS。

不設定外部模型也能用：評分標準改用內建的，找候選用的畫面描述由地端模型寫，初選完全在地端完成。

## 定義一場比賽

比賽怎麼定義，決定了 AI 用什麼標準看你的照片。按「新增比賽」會開啟問答精靈，共六步，每一步都可以跳過：

1. **比賽**：名稱和主題。手邊有簡章的話可以整段貼上，地端模型會讀出主題、規則、拍攝期間、張數上限和評審方式。
2. **評審與目標**：選擇題。誰來評（專業評審、主管同事、大眾票選）、主題要多切題、你想得獎還是想展現個人風格、希望作品給人什麼感覺。
3. **規則**：拍攝期間、直橫式、解析度、器材、人物、張數上限。畫面會即時顯示有多少照片符合。
4. **追問**：地端模型讀完前面的回答，針對還模糊的地方出幾題選擇題，例如「有人的畫面算不算寧靜」。
5. **用照片討論**：app 從你的相片庫挑 8 張風格各異的照片，請你標「符合、普通、不符合」；第二輪再給 8 張它最沒把握的。然後地端模型看你選的和沒選的，說出它觀察到的差異和你想找的是什麼，你可以直接改它的結論。
6. **確認**：列出全部內容和每一層會篩到剩幾張，確認後建立。

追問和照片討論都在地端進行，照片不會離開電腦。建立時，整份問答紀錄以文字交給外部模型寫評分標準；它會先用白話列出「我打算這樣評你的照片」，你覺得不對可以修改比賽定義再重新產生。

你標為「符合」的照片一定會進入候選，標為「不符合」的一定不會。

## 後製

在照片檢視畫面按 `E`（或點「後製」）進入修圖。只做整體調整、裁切和轉正，不會移除或添加畫面裡的任何東西，符合多數比賽「不可合成」的規定。

- **調整項目**：曝光、對比、亮部、暗部、色溫、色調、自然飽和度、飽和度、黑白、清晰度、銳利化、暗角、轉正、裁切（含常用比例）。
- **地端模型建議**：按「請地端模型建議」，模型會決定後製方向並直接套用。勾選「套用後自我複查」時，app 會把修圖前後的對照再給模型看，讓它修正過頭或不足的地方。不花 token。
- **外部評審的建議**：決選時，外部模型會順便為每張入圍照片提出調整建議，包在同一次呼叫裡，不需要另外上傳照片。在比賽名次列表按「後製」，再按「套用」即可。
- **外部模型複查**：對自己修的結果沒把握時，可以請外部模型看一眼。只上傳一張前後對照的縮圖，實測一次約 1,900 tokens。
- **匯出**：修圖只記錄成一組調整步驟，原始檔不會被更動，隨時可以重設。匯出時才以完整解析度產生一份 JPEG 複本，保留原本的拍攝資訊與色彩描述檔。比賽匯出時，修過圖的照片會多一份修圖後的版本。

按住空白鍵（或畫面下方的按鈕）可以看原圖。滑桿上按兩下會歸零。

模型擅長判斷方向（該提亮、該裁掉哪一邊），但給不出精準的數值，所以幅度是這樣決定的：模型給方向和強弱，app 量測照片實際偏離正常多少來決定要調多少。夜景、日落、表演現場這類本來就暗的照片不會因為量測而被提亮。轉正的角度也是量出來的，只有在建築或明確的地平線上才準，其他情況請自己用滑桿調。

## 投稿

決選完成後，比賽頁面的第 5 步「投稿」會把評審建議的作品帶進投稿名單（可以自己增減、調整順序）。相機原始檔常常一張就 40–50 MB，所以分兩次交：

**第一步：初審包。** 每件作品輸出一張縮小的 JPEG，加上一份作品說明，整包通常只有幾 MB。

- 尺寸、單檔大小上限和說明字數上限可以設定；用問答精靈貼簡章時，地端模型會順便讀出這些規格。檔案超過大小上限時先降低 JPEG 品質，還是太大才縮小尺寸；不會把小圖放大。
- 一律轉成 sRGB。手機拍的 Display P3 照片若不轉換，在不支援色彩管理的螢幕上顏色會變淡。
- 照片內的拍攝資訊（EXIF）預設完整保留，包含 GPS 位置，因為有些比賽會用它確認拍攝時間。不想讓主辦單位看到拍攝地點的座標，可以改成「移除 GPS」或「全部移除」。
- 有修圖的作品可以選擇投原圖或投修圖後的版本。
- 打包前會列出可能被退件的問題：超過件數上限、不在規定的拍攝期間、解析度不足、說明超過字數、兩件作品來自同一組連拍等。

**作品說明怎麼寫出來的。** 分成兩部分：

- 拍攝時間、地點、器材、光圈快門這些事實，直接取自照片檔本身，不經過模型。
- 說明文字由外部模型起草，而且**只送文字，照片不會再上傳**：送出的是地端模型對畫面的描述、評審寫的優點，以及你對「拍攝背景」問題的回答。實測三件作品約 2,700 tokens。沒有外部模型時也可以改用地端模型寫。

「拍攝背景」是關鍵。當時為什麼停下來拍、這個畫面對你的意義，這些只有你知道。地端模型會看著每張照片問你兩個問題並附上選項，點選或自己寫都可以。模型被明確要求不可以編造沒被提到的經歷（等了多久、當時的天氣、你的心情）；沒有回答背景問題的作品，說明只會寫畫面本身和它與主題的關係。**送出前請務必自己讀過，改成你自己的話**，尤其要確認裡面沒有不符事實的內容。

說明超過字數上限時，會請模型精簡一次；仍然超過的話會在檢查清單裡標出來，由你手動刪減，不會從句子中間截斷。

作品說明輸出成一份 `作品說明.html`，圖片內嵌在檔案裡，可以單獨寄出；用瀏覽器開啟後列印就能存成 PDF，每件作品一頁。

**第二步：完整包。** 收到初審結果後，把通過的作品標記為「通過初審」，再建立完整包。只有通過的作品會被放進去：

- 原始檔，逐位元組複製，和相片庫裡的檔案完全相同
- 配對的 RAW 檔（有的話）
- 修圖後的全尺寸 JPEG（有投修圖版本的話），保留原本的色彩描述檔與拍攝資訊
- 同一份作品說明

建立前會顯示預估大小。可以選擇是否另外打包成一個 zip（不壓縮，只是合成一個檔案，會多占一份空間）。

兩種包都只是複製，原始檔不會被更動。第 4 步的「匯出入圍照片與評審報告」則是給自己留存用的，裡面有評審的完整評語，不適合直接交給主辦單位。

## 安裝（macOS）

需要 Apple Silicon 的 Mac，以及已安裝的 [Ollama](https://ollama.com)。

1. 安裝 [uv](https://docs.astral.sh/uv/)（Python 的套件管理工具，會自動準備好 Python）：

   ```bash
   curl -LsSf https://astral.sh/uv/install.sh | sh
   ```

2. 取得程式並安裝相依套件（含 PyTorch，需要幾分鐘）：

   ```bash
   git clone https://github.com/kuanhuasu-source/PhotoSift.git
   ```

   ```bash
   cd PhotoSift && uv sync --no-dev
   ```

3. 下載地端模型。64 GB 記憶體建議這兩個（合計約 28 GB）：

   ```bash
   ollama pull gemma4:12b
   ```

   ```bash
   ollama pull gemma4:31b
   ```

   `gemma4:12b` 負責大量標註（速度優先），`gemma4:31b` 負責比賽初選（判斷力優先）。記憶體較小的電腦，設定頁會依記憶體大小建議其他模型。

4. 啟動：

   ```bash
   uv run photosift
   ```

   會開啟 PhotoSift 視窗。第一次分析照片時，會從 Hugging Face 下載影像分析模型（約 1.5 GB）。

5. 想要一個可以放進 Dock 的圖示：

   ```bash
   ./scripts/make_mac_app.sh
   ```

   會在專案資料夾產生 `PhotoSift.app`。它是一個啟動器，執行的就是這個資料夾裡的程式，所以建立之後不要搬動專案資料夾。

也可以用瀏覽器開啟，不開視窗：`uv run photosift --browser`。

## 開始使用

1. 到「設定」加入相片資料夾，按「開始分析」。幾千張照片大約需要幾分鐘到十幾分鐘，可以隨時取消，下次會接著做。
2. 在「設定」的地端模型選好標註模型和評審模型。
3. 回到「圖庫」按「地端模型標註」。它會從最有潛力的照片開始處理，不必一次跑完。
4. 要用外部模型的話，在「設定」選一家、貼上 API key、選好模型。
5. 到「比賽選片」新增比賽，填上主題和規則，照畫面上的四個步驟做。

在照片檢視畫面可以用鍵盤：`←` `→` 切換、`P` 挑選、`X` 淘汰、`0`–`5` 給星等、`E` 後製、`Esc` 關閉。

## 外部模型

| 提供者 | 預設模型 | 備註 |
|---|---|---|
| Claude | `claude-opus-5-5` | 透過官方 SDK。已啟用伺服器端的拒絕回退：若安全分類器拒絕某次請求，API 會自動改用它建議的模型重試。已用 `ant auth login` 登入的話可以不填 key |
| Gemini | `gemini-flash-latest` | |
| GPT | 無預設 | 模型名稱更新得很快，請儲存 key 之後按「列出可用模型」挑選 |

API key 存在 macOS 的鑰匙圈。也可以用環境變數 `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`、`GEMINI_API_KEY`。

「設定」最下方有每個模型的呼叫次數與 token 用量。填入你所用模型的單價，會一併顯示估計費用。

### 用訂閱而不是 API key（實驗性）

Claude 和 GPT 可以改走官方的命令列工具，用你已經登入的訂閱帳號，不需要 API key。在「設定」的外部模型選 Claude 或 GPT，把上方的切換鈕從「API key」改成訂閱。

| | 需要先安裝並登入 | 登入方式 |
|---|---|---|
| Claude 訂閱 | [Claude Code](https://code.claude.com) | 在終端機執行 `claude`，輸入 `/login` |
| ChatGPT 訂閱 | [Codex CLI](https://developers.openai.com/codex/cli) | 在終端機執行 `codex login`，選擇用 ChatGPT 帳號登入 |

運作方式：PhotoSift 在背景執行該工具的非互動模式（`claude -p` 或 `codex exec`），把縮小後、已移除拍攝資訊的照片放在暫存資料夾交給它，讀回它輸出的 JSON，然後刪除暫存檔。Claude Code 只被允許使用讀檔工具，Codex 以唯讀沙箱執行。

設定好之後請按「測試連線」，它會送一張純色的小圖確認整條路是通的。

要知道的幾件事：

- **比 API 慢**。工具每次啟動都有固定開銷，每批照片大約一到兩分鐘。
- **用量計入訂閱額度**，而且工具本身的系統提示會多用一些。
- **Claude 的使用政策**：Anthropic 的文件說明訂閱登入是給訂閱者本人使用，開發產品應該用 API key，同時也說這不妨礙使用者用自己的訂閱登入未修改的 Claude Code。個人在自己電腦上用腳本呼叫官方工具沒有被明文涵蓋，政策若有變動請以官方說明為準。
- 環境裡如果設了 `ANTHROPIC_API_KEY` 或 `OPENAI_API_KEY`，PhotoSift 在執行工具時會把它們拿掉，確保走的是訂閱登入而不是按量計費。
- **Gemini 沒有這個選項**。查到的資料顯示個人訂閱目前不能用於 Gemini CLI，所以 Gemini 仍然只能用 API key。

## 地端模型

預設連到 `http://localhost:11434` 的 Ollama。也可以在設定的「進階」改成 LM Studio 或其他 OpenAI 相容的本機服務。

比賽頁的校準步驟會顯示地端評審和外部評審的「排序一致度」。想比較兩個地端評審模型（例如 `gemma4:31b` 和 `qwen3-vl:32b`）哪個比較準，各跑一次看這個數字就知道。

## 資料放在哪裡

分析結果、縮圖和設定存在 `~/Library/Application Support/PhotoSift/`。刪掉這個資料夾就會回到全新狀態，你的照片不受影響。設定環境變數 `PHOTOSIFT_HOME` 可以改放別處。

支援 JPEG、HEIC、PNG、TIFF、WebP 與常見的 RAW 格式（CR2、CR3、NEF、ARW、RAF、RW2、ORF、DNG 等）。同名的 RAW 和 JPEG 視為同一張，匯出時會一起複製。

## 驗證狀況

這個版本是在 Linux 雲端環境開發的，以下是實際測過和還沒測過的部分。

已實測：

- 82 個自動化測試（`uv run pytest`），涵蓋匯入、品質判定、分組、事件切分、光線時段、偏好模型、比賽規定過濾、主題召回、總表初選、問答精靈、修圖引擎、後製建議、投稿包（尺寸與大小上限、sRGB 轉換、EXIF 處理、完整包只含通過的作品）、API，以及「原始檔不被更動」「金鑰不外洩」「上傳的複本不含拍攝資訊」「寫作品說明時不上傳照片」等保證。
- 用真的 SigLIP 2 模型跑過影像分析與中文搜尋。
- 用 Gemini 跑過完整的比賽流程（評分標準、校準、總表初選、決選與後製建議）和修圖複查。
- 問答精靈從貼上簡章到建立比賽，用真模型在介面上完整操作過。
- 用瀏覽器從介面操作過完整流程，包含修圖、套用建議與匯出，沒有錯誤。
- 投稿流程用真模型在介面上完整操作過：地端模型提問、Gemini 只讀文字寫作品說明、建立初審包、標記通過、建立完整包，並檢查了輸出檔的尺寸、色彩描述檔、拍攝資訊，以及作品說明列印成 PDF 的結果。

還沒實測，第一次在 Mac 上執行時請留意：

- **真正的 Ollama**。開發環境無法安裝 Ollama，地端模型的部分（標註、評審、後製建議）是用一個替身服務測的：它實作同樣的 Ollama API，背後接的是雲端代管的 Gemma 4。
- **原生視窗與資料夾選擇器**（pywebview）和 `make_mac_app.sh`。這些只能在 macOS 上執行。若視窗開不起來，`uv run photosift --browser` 的功能完全相同。
- **Apple GPU（MPS）加速**、**HEIC 與 RAW 檔**的實際讀取與修圖。
- **iPhone 照片的色彩**。iPhone 照片使用 Display P3 色域，程式會把色彩描述檔一路帶到預覽和匯出檔，但手邊沒有真正的 P3 照片可以驗證顏色是否完全一致。
- **Claude 與 GPT**。開發環境沒有這兩家的金鑰，程式是依官方文件寫的，沒有對真實 API 呼叫過。
- **訂閱（命令列工具）這條路**。參數是對照實際安裝的 Claude Code 2.1 和 Codex CLI 0.172 的說明寫的，但開發環境沒有可用的訂閱登入，所以只用模擬的工具測過流程。特別是「Claude Code 用讀檔工具看照片」這一步，請先用「測試連線」確認。
- 清晰度的判定門檻是用網路尺寸的範例照片調的，實際相機檔可能需要在設定裡調整「模糊判定門檻」。
- **投稿包遇到真正的大檔**。範例照片每張不到 1 MB、長邊 1920 像素，所以「40–50 MB 的原始檔縮成幾 MB」只在自動化測試裡用合成的大圖驗證過；HEIC、RAW 配對檔和 Display P3 照片的轉換也還沒用真實檔案跑過（P3 轉 sRGB 是用自製的廣色域描述檔測的）。
- **作品說明的品質**取決於你回答了多少拍攝背景，以及外部模型是否守規矩。實測中模型沒有編造經歷，但會把畫面的構圖寫成「我刻意這樣拍」，這類語句請自行確認是否屬實。
- **大型相片庫**。開發時的範例只有 37 張，所以「5,000 張以上」的表現（召回的品質、偏好模型的效果、地端標註要花多久）還沒有實際量過。主題召回和總表初選的張數都可以在比賽設定裡調整。
- **光線時段**需要相機有記錄時區（iPhone 和近年的相機都有）。沒有記錄時只會標出明顯的白天和夜晚。
- 後製建議的幅度是用少量範例照片調的。如果覺得模型普遍修得太多或太少，告訴我方向，可以再調。

## 開發

```bash
uv sync
```

```bash
uv run pytest
```

測試不需要下載模型，也不會連網。

`scripts/fetch_samples.py` 會從 Wikimedia Commons 下載一批自由授權的照片當示範相片庫，並產生 `CREDITS.json` 記錄每張的作者與授權。`scripts/dev_ollama_shim.py` 是上面提到的 Ollama 替身，僅供開發測試；使用它時照片會送到外部，不要拿來處理私人照片。

程式結構：

```
photosift/
  ingest.py      匯入：掃描、EXIF、縮圖
  quality.py     技術品質
  embedder.py    影像與文字的向量
  taxonomy.py    主題分類與美感初評
  grouping.py    連拍分組、事件、初步分數
  local_vlm.py   地端視覺語言模型
  cloud/         Claude、GPT、Gemini（API），以及透過官方命令列工具使用訂閱
  sun.py         由時間和 GPS 計算光線時段
  taste.py       從挑選與淘汰學習偏好
  wizard.py      比賽定義精靈：追問、挑範例照片、歸納偏好
  contest.py     比賽選片：規定過濾、候選召回、地端評審、校準、總表初選、決選
  editing.py     修圖引擎：把一組調整套用到複本上
  retouch.py     後製建議：模型給方向、量測定幅度、複查修正
  server.py      本機 API
  web/           介面
```

介面使用 [Preact](https://preactjs.com)（MIT）與 [htm](https://github.com/developit/htm)（Apache-2.0），已包含在 `photosift/web/vendor/`。
